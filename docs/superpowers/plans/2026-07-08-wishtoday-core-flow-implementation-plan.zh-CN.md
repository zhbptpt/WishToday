# WishToday 第一版核心流程开发实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 WishToday 第一版核心链路：今日推荐 -> 鸡尾酒详情 -> 实验台改造 -> 预览 -> 登录保存 -> 个人配方详情 -> 私人笔记本。

**Architecture:** 当前工作区尚未包含应用代码脚手架，因此本计划先锁定功能边界、任务顺序、数据流、页面交付物和验收标准。进入代码实现前，执行者必须先确认或创建实际 App 工程，再将本计划映射到项目既有目录结构。

**Tech Stack:** 待应用脚手架确认；本计划不指定框架，不伪造不存在的文件路径。

## Global Constraints

- 首次打开 App 直接进入首页，不强制登录。
- 登录 / 注册只在保存私人配方时触发。
- 登录 / 注册成功后必须继续执行 `saveRecipe`，不能跳首页。
- 详情页第一版只有一个主行动：「按此配方去实验台」。
- 实验台只支持基于经典鸡尾酒导入后改造，不支持从零创建。
- 预览页只支持「保存到私人笔记本」，不支持发布。
- 个人配方详情页第一版只读，不支持编辑、删除、分享。
- 私人配方笔记本只做创建时间倒序列表，不支持搜索、筛选、收藏、删除。
- 被标记为第一版不做的功能不得通过头部按钮、底部按钮或更多菜单加回。

## Task 1：工程基线与路由骨架

**交付物：**

  - `/cocktails/:cocktailId`

  - `/recipes/:recipeId`

## Task 2：核心领域模型与示例数据

**目标：** 定义核心流程所需的最小数据结构，先用示例数据打通页面。

**核心模型：**
- Cocktail：经典鸡尾酒
- Ingredient：材料
- DiyDraft：DIY 草稿
- SavedRecipe：已保存私人配方
- UserSession：用户登录状态

**最小字段：**
```text
Cocktail:
id, nameZh, nameEn, imageUrl, recommendationText, baseSpirit, glassType,
alcoholLevel, difficulty, flavorTags, flavorRadar, ingredients, steps, bartenderNotes

Ingredient:
id, name, category, description, alcoholLevel

DiyDraft:
sourceCocktailId, sourceCocktailName, name, nameEn, baseSpirit,
ingredients, flavorTags, notes, isDirty

DraftIngredient:
ingredientId, name, category, amount, unit, stepOrder

SavedRecipe:
id, sourceCocktailId, sourceCocktailName, name, nameEn, baseSpirit,
ingredients, flavorTags, notes, createdAt

UserSession:
isAuthenticated, userId, nickname
```

**步骤：**
- [ ] 定义上述模型。
- [ ] 准备至少 7 条今日推荐鸡尾酒示例数据。
- [ ] 准备覆盖所有材料分类的材料示例数据。
- [ ] 准备本地内存或本地模拟仓库，用于保存私人配方。
- [ ] 验证示例数据可以支撑首页、详情、实验台、添加材料、预览、笔记本展示。

**验收：**
```text

详情页可以按 cocktailId 读取完整鸡尾酒
实验台可以从 Cocktail 生成 DiyDraft
```
